## P0 — Critique (à corriger immédiatement)

### P0.1 — Le VIP par abonnement ne s'active JAMAIS
`src/app/api/stripe/webhook/route.ts:209,231`. Le webhook lit `subscription.current_period_end`, mais dans le SDK Stripe installé (apiVersion `2025-12-15.clover`) ce champ a migré sur l'**item** d'abonnement (`SubscriptionItems.d.ts:53`) — vérifié : absent de `Subscriptions.d.ts`. Au runtime `undefined * 1000 = NaN` → `new Date(NaN).toISOString()` lève `RangeError` → `catch` → **500** → Stripe retente en boucle, `is_vip` reste `false`.
**Impact** : tout abonnement VIP payé (12,99 €/mois) n'active aucun avantage. Masqué par un test au mock périmé.
**Fix** : lire `subscription.items.data[0].current_period_end` (fallback `subscription.current_period_end`).

## P1 — Majeur

### P1.1 — Fuite PII + secret provably-fair : tout connecté lit tous les profils
`supabase/migrations/20260609190002_profiles_pii_anon.sql:19` — `GRANT SELECT ON public.profiles TO authenticated` (table entière). RLS `USING(true)` ⇒ n'importe quel compte connecté lit **toutes les colonnes de tous les profils** : `fair_server_seed` (casse l'équité des mini-jeux → prédiction des résultats → **mint de crédits**), `shipping_*` (PII livraison RGPD), `vip_subscription_id`.
**Fix (NON hot-fixable)** : un `REVOKE SELECT (fair_server_seed)` seul est inopérant (le `GRANT SELECT` table-entière couvre déjà toutes les colonnes). Le vrai fix = `REVOKE SELECT ON profiles FROM authenticated` + `GRANT SELECT (colonnes sûres)`, MAIS `profiles.select('*')` est utilisé par `(main)/layout.tsx`, `profile/page.tsx`, `adminCheck.ts`, `auth.ts` (client authentifié) → casserait toute l'app. Deux chemins propres : (a) convertir ces `select('*')` en listes de colonnes explicites (sans `fair_server_seed`) puis revoke+grant ; (b) déplacer `fair_server_seed`/`nonce` dans une table `user_fairness` service-role only. À faire avec tests, pas à chaud sur la DB live (d'autant que billing en grace-period).

### P1.2 — Auto-remboursement d'un achat de pack déjà crédité (replay d'event)
`src/app/api/stripe/webhook/route.ts:187-198`. Si une même session arrive sous **deux event.id** (replay dashboard), la 2e passe la gate `stripe_events`, `grant_pack_credits` renvoie `{granted:0, error:'already_processed'}`, et le webhook interprète `granted<=0` comme « payé mais 0 crédit » → **rembourse** un achat déjà honoré.
**Fix** : traiter `error ∈ {already_processed, monthly_limit_reached sur retry}` comme succès idempotent (200, pas de refund).

### P1.3 — Buy It Now : payé mais non enregistré, sans remboursement
`src/app/api/stripe/webhook/route.ts:142-153` + `20260614150001_buy_it_now.sql:97`. `record_buy_it_now` renvoie `{ok:false,'game_not_found'}` **sans** erreur SQL (ex. partie supprimée par create-rotation avant le paiement). Le webhook ne teste que `binError` → renvoie 200 sans rien enregistrer ni rembourser. **Client débité, lot non tracé/expédié.**
**Fix** : tester `binResult.ok === false` → refund (comme le flux packs) ou log CRITICAL + alerte.

### P1.4 — Le reset quotidien efface le bonus `equip_daily_clicks`
`src/app/api/cron/reset-credits/route.ts:103,113` met `credits = 10/20` en dur, alors que la RPC `reset_daily_credits` fait `+ COALESCE(equip_daily_clicks,0)`. Le cron (minuit, prioritaire via `last_credits_reset`) gagne la course → le perk de clics quotidiens (gagné en coffre/pass) est **annulé chaque jour**.
**Fix** : ajouter `+ equip_daily_clicks` aux deux updates du cron (ou appeler la RPC).

### P1.5 — Bouton « Recharger » de la page cadeau cassé
`src/app/(main)/cadeau/merci/page.tsx:34` — `<Link href="/cadeau/merci">` sans `?session=` → l'utilisateur reste bloqué à jamais sur « On prépare ton cadeau… ».
**Fix** : composant client + `router.refresh()`, ou propager `?session=`.

### P1.6 — Race TOCTOU sur la clôture de partie
`src/app/api/cron/bot-clicks/route.ts:166,325`. `endGame` détermine le gagnant depuis le snapshot lu en début de boucle (pas de `FOR UPDATE`, pas de revérif `end_time<=now` sous verrou). Fenêtre = la dernière seconde : un `perform_click` concurrent (qui étend `end_time`) peut voir la partie close sur l'ancien leader → mauvais gagnant / clic facturé sur partie close.
**Fix** : déplacer la clôture dans une RPC `end_game(p_game_id)` SECURITY DEFINER avec `SELECT … FOR UPDATE` + revérif `end_time`.

### P1.7 — Dette de types : ~100 `as any`
`src/lib/supabase/database.types.ts` obsolète (~12 tables + ~15 RPCs de juin 2026 manquantes) → casts `(supabase as any)` partout. `npm run db:types` en résorbe l'essentiel.

## P2 — Moyen
- **Storage avatars** (`20260123000006_storage_policies.sql`) : policies INSERT/UPDATE/DELETE sans `owner = auth.uid()` → n'importe qui écrase/supprime l'avatar d'autrui. Pinner le propriétaire (`(storage.foldername(name))[1] = auth.uid()::text`).
- **`getGameContenders` perf** (`src/actions/game.ts`) : 400 lignes × N spectateurs × /30s, dédup en JS. Remplacer par RPC `COUNT(DISTINCT username)` + léger cache.
- **`get_gift_code` anon sans rate-limit** : brute-force théorique (espace 30¹⁰ énorme, risque faible). Rate-limit Upstash ou exiger `authenticated`.
- **5× `new Stripe()` dupliqués** (webhook + 4 actions), le webhook omet `timeout`/`maxNetworkRetries`. Centraliser `getServerStripe()`.
- **2 hooks de simulation bot quasi identiques** (`useBotSimulation` / `useLobbyBotSimulation`, ~600 l.).
- **`eslint-config-next@15` désaligné** avec `next@16`.
- **`<Image fill>` sans `sizes`** sur vignettes (GameHistorySection, ProfileClient, ScratchCard…).
- **Tests manquants** sur chemins payants : remboursement auto, Buy-It-Now, gift, cron bot-clicks.

## Ce qui est SOLIDE (vérifié adversarialement)
- Prix **toujours** fixés/recalculés côté serveur (packs, VIP, pass, Buy-It-Now via `quote_buy_it_now`, gift) — aucune manipulation de montant.
- Idempotence Stripe en cas nominal : `stripe_events` (PK event.id) + ledgers par session (`credit_grant_sessions`, `pack_purchases` ON CONFLICT, `UNIQUE(stripe_session)` gift, `UNIQUE(user_id,game_id)` BIN). Pas de double-crédit sur retry standard.
- x2 1er achat **atomique** (`INSERT … ON CONFLICT DO NOTHING` + ROW_COUNT).
- Crédits achetés/récompensés → `earned_credits` (permanents) ; `credits` seul reset. Aucune perte de donnée permanente trouvée.
- RLS activé sur 31 tables ; tables backend-only en default-deny ; `search_path` sur toutes les DEFINER post-durcissement ; anti-IDOR `auth.uid()` systématique ; trigger `protect_profile_sensitive_columns` (INVOKER) couvre credits/wins/xp/is_vip/fair/equip…
- `perform_click` atomique (double FOR UPDATE), anti-spoof username, débit daily→earned.
- `endGame` : double-fin évitée (garde statut atomique + `winners.game_id UNIQUE`).
- Provably-fair commit-reveal correct (seed secret service_role only) — **sauf** la fuite P1.1 qui le contourne.
- Headers/CSP solides (`'unsafe-eval'` dev only), open-redirect callback bloqué, crons fail-closed, aucun secret en dur, `.env.example` complet.
- Wrapped : OG edge fonctionnel, PII clean, `notFound()` géré. Gift : flux idempotent/atomique exemplaire. DA exemplaire (0 emoji UI, 0 faute d'accent).
