## 0. Verdict en une page

**Le code applicatif est sain et déjà très durci.** Portail qualité 100 % vert (tsc 0 erreur, eslint 0/0, 86 tests unit PASS), les deux corrections critiques historiques **tiennent** à l'analyse adversariale (exploit `fair_server_seed` fermé, TOCTOU `end_game` corrigé), le webhook Stripe est signé + idempotent, la RLS `profiles` own-row et le gating admin sont solides, `src/proxy.ts` (= middleware Next 16) est bien actif en prod (nonce CSP + headers + rate-limit API). Aucun chemin « gagner un lot sans payer » ni « prédire l'issue » trouvé.

**MAIS l'audit fait remonter un risque de nature différente, et plus grave que tout bug technique : le risque légal/réglementaire de fond.** La jauge ×2 est **live en prod** (`GAUGE_ENABLED = true`, `GAUGE_MULTIPLIER = 2`, qualifiée de « LEVIER JURIDIQUE » dans le code), combinée à un penny-auction en argent réel avec des **bots opérés par Cleekzy qui désignent des gagnants**, le tout dans des CGU qui affirment « ce n'est pas un jeu de hasard ». C'est un cumul qui expose à une requalification en jeu d'argent soumis à agrément ANJ et à une qualification de pratique commerciale trompeuse.

## 3. Les P0 en détail (consolidés, dédupliqués)

### CLUSTER LÉGAL — existentiel (à trancher avec un avocat AVANT lancement payant)

**P0-1 — Modèle de fond probablement requalifiable en jeu d'argent (agrément ANJ).**
Penny-auction en argent réel + **jauge ×2 garantie live** (`src/lib/utils/constants.ts:17-18`, webhook `route.ts:260`, `terms/page.tsx:57-66`). Le code lui-même qualifie le ×2 de « LEVIER JURIDIQUE ». Risque : exploitation illégale de jeu d'argent → sanctions pénales + fermeture. *Décision business, mais doit être documentée et validée juridiquement.*

**P0-2 — Bots opérateur non divulgués + CGU mensongères.**
`bot-clicks/route.ts:267,335-419` : les bots Cleekzy cliquent, **désignent le gagnant** (`winners.is_bot`) et relancent le timer sur des enchères en argent réel. Les CGU n'interdisent les bots qu'aux *joueurs* (`terms:97-102`) et affirment « CLEEKZY n'est pas un jeu de hasard / pas d'algorithme aléatoire » (`terms:65`). → pratique commerciale trompeuse (art. L121-2 C. conso) + aggrave la requalification.

**P0-3 — Vérification d'âge 18+ purement cosmétique.**
`auth.ts:118-175` + `register/page.tsx:248-258` : case 18+ côté client, `signUp` ne l'exige pas serveur (contournable), aucun contrôle au paiement. Obligation de protection des mineurs non satisfaite pour un service payant de type jeu.

### CLUSTER FINANCIER / SÉCU — exploitable

**P0-4 — INSERT direct non contraint sur `clicks`.**
La policy `WITH CHECK (user_id = auth.uid())` + GRANT INSERT par défaut laissent un joueur connecté **forger des lignes `clicks`** (`credits_spent`/`is_bot`/`game_id` arbitraires). Impact : baisse artificielle du prix « Rachat malin » (objet physique au plancher), farm de badges créditant `earned_credits`, pollution du feed, bypass `can_comment`. → `REVOKE INSERT ON clicks FROM authenticated` (tout clic légitime passe par `perform_click` service_role). *Vérifié au niveau schéma.* Détail : `01-securite-auth-rls.md`.

**P0-5 — Clawback ne révoque pas l'item physique gagné via la jauge.**
Un remboursement/chargeback d'un pack de crédits **ne touche jamais `gauge_wins`** → le joueur garde l'item physique ET récupère son argent. Détail : `02-paiement-economie.md`.

**P0-6 — Clawback n'annule pas un buy-it-now.**
La session buy-it-now est absente de `credit_grant_sessions` → le clawback renvoie `session_not_found`, `buy_it_now_purchases` reste `pending` → item physique gratuit + argent rendu. Détail : `02-paiement-economie.md`.
*Note transverse : ces deux trous (P0-5/6) ne se déclenchent QUE si les events `charge.refunded` / `charge.dispute.created` sont abonnés sur l'endpoint Stripe — à vérifier côté dashboard (sinon tout l'anti-fraude est mort-code).* 

### CLUSTER INFRA / SEO / A11y / TESTS

**P0-7 — Secrets PROD réels dans `.env.local`.** service_role (219c), OpenAI, Resend, CRON_SECRET, VAPID. Le fichier n'est pas commité (gitignore OK) mais les secrets doivent être **rotationnés** (exposition locale, déjà signalé le 06-17, toujours présent). Détail : `09-infra-config-observabilite.md`.

**P0-8 — Pages privées indexables.** `/shop` `/vip` `/mini-games` sont dans `sitemap.ts:38-54` mais font `redirect('/login')` pour Googlebot (pages mortes indexées) ; `/profile` `/collection` `/clans` non bloquées dans `robots.txt`. Détail : `11-seo-metadata-contenu.md`.

**P0-9 — 9/12 modales sans focus trap/Échap/restauration.** `useModalA11y` existe mais n'est branché que sur 3 modales ; SpotlightTour et IOSInstallTour (onboarding + install PWA) non navigables au clavier. Détail : `06-a11y-ux-pwa.md`.

**P0-10 — Chemin argent 100 % non testé.** Aucun test sur : webhook Stripe POST (signature/idempotence — les tests appellent `handleStripeEvent` en bypass), jauge cash (increment/double-mint/abandon), codes cadeau (redeem/void/double-redeem), buy-it-now (recalcul prix serveur). Une régression sur ces chemins passerait la CI au vert. Détail : `10-tests-fiabilite-ci.md`.

## 4. Thèmes transverses (un même problème vu par plusieurs agents)

1. **La jauge ×2 est LIVE, pas dormante.** Les commentaires de migration (`120003`) et l'hypothèse de l'agent jeu disent « inerte » — c'est **faux** (`GAUGE_ENABLED=true`, webhook l.260). Conséquences en cascade : exposition légale réelle (P0-1), `purchased_value_cents` alimenté en prod (DB P1), non-atomicité `perform_click`↔`increment_item_gauge` désormais **active** (game, requalifié), clawback `gauge_wins` manquant (P0-5). → **Action n°1 : décider du sort de la jauge** (la couper en repassant `GAUGE_ENABLED=false` le temps de l'avis juridique est un quick win défensif d'une ligne).

2. **Self-exclusion incomplète.** Fail-closed et 8 call-sites OK, mais `redeemGift` n'a pas de garde (paiement P1 + légal P1) → un joueur en pause peut se recréditer. + pas d'invalidation globale de session à l'exclusion.

3. **Drift de types Supabase → 70 `as any` sur le chemin argent.** La feature jauge+clawback est absente de `database.types.ts`, donc les RPC monétaires sont appelées en `(supabase.rpc as any)` (DB P1 + qualité P2). Cause racine : bug `.rpc` de `@supabase/ssr@0.5.2`. → un wrapper `callRpc` typé + `db:types` régénéré tue 70 casts + 105 `eslint-disable` et rend le typage au chemin le plus sensible.

4. **Fail-open du rate-limit en serverless.** Sur erreur/absence d'Upstash, retombée sur un store mémoire par-instance (sécu P1 + infra P2) → plafonds anti-stuffing/anti-clic quasi contournables. `UPSTASH_*` même pas dans `envValidation.ts`.

5. **framer-motion réinjecté dans le baseline.** Le fix « CookieConsent » du 06-17 a déplacé le problème : `InstallBanner` + `BadgeNotificationContainer` du layout `(main)` ré-embarquent le chunk framer (~123 KB) dans toutes les routes (perf P1). Même classe de bug, une couche plus bas.

6. **Dépendance SPOF cron-job.org.** `bot-clicks` et `create-rotation` n'ont AUCUN filet Vercel (infra P1) : si cron-job.org tombe → lobby vide + parties jamais clôturées + gagnants jamais désignés, panne silencieuse.
