## P0 — Critique
### P0.1 — Le bandeau cookies ne bloque RIEN (non-conformité CNIL)
`src/components/common/Analytics.tsx` charge Umami **inconditionnellement** ; `src/lib/analytics.ts` `trackEvent`/`trackSignup`/`trackPurchase` firent toujours. Le `CookieConsent` stocke accepted/refused en localStorage mais **personne ne le lit**. « Refuser » ne désactive rien. → consentement préalable non respecté.
**Fix** : gater `<Analytics/>` + `trackEvent` sur le consentement.

## P1 — Majeur
### P1.1 — Fuite PII vers tout compte `authenticated` (pré-existant, non corrigé)
`GRANT SELECT ON profiles TO authenticated` (table entière) + RLS `USING(true)` → tout connecté lit les `shipping_*` (adresse/téléphone), `vip_subscription_id`, `is_admin`, `referred_by` de **tous**. Le fix PII de juin n'a fermé que `anon` ; j'ai sorti `fair_server_seed` mais pas le reste. Violation RGPD.
**Fix** : RLS own-row pour les colonnes sensibles OU grants colonne pour authenticated + RPC pour son propre profil complet (comme fair_server_seed). Complexe (les `select('*')` du layout/profil).

### P1.2 — Auto-exclusion CONTOURNABLE
- **Mini-jeux** : `playMiniGame`/`playMiniGamePaid` (`miniGames.ts:100,207`) ne vérifient PAS l'auto-exclusion alors qu'ils dépensent des crédits + lancent du hasard. Atteignable via l'UI.
- **perform_click** : la RPC (GRANT authenticated) n'a aucun check ; un joueur en pause peut cliquer en appelant la RPC directement. La garde n'est que dans la Server Action `clickGame`.
**Fix** : check `selfExcludedUntil` dans playMiniGame(+Paid) ; check `user_self_exclusion` dans la RPC `perform_click`.

### P1.3 — OAuth Google contourne la case 18+/CGU
`register/page.tsx:241` — le bouton Google (`onClick handleOAuth`) est HORS du `<form>` ; la checkbox `required` (dans le form) ne s'applique pas. Un mineur peut créer un compte via Google sans cocher 18+.
**Fix** : désactiver/garder les boutons OAuth tant que la case n'est pas cochée (état partagé).

### P1.4 — Pages légales : `<main>` imbriqué + double chrome
`jeu-responsable` & `comment-ca-marche` rendent leur propre `<main>` DANS le `<main>` du `(legal)/layout` → double landmark (HTML/a11y invalide) + le kicker/hero/CTA s'affichent dans la carte légale (incohérent avec cgv/privacy qui font `<article prose>`).
**Fix** : suivre le pattern des pages sœurs (retirer `<main>` + chrome).

### P1.5 — `/jeu-responsable` : texte obsolète + promesse non tenue
La page dit que l'auto-exclusion passe « par email sous 48h » (faux : self-service instantané au profil) et propose une « limite de dépense » par email (NON implémentée).
**Fix** : lier vers la section « Faire une pause » du profil ; retirer ou implémenter la limite de dépense.

### P1.6 — CGV obsolètes
`cgv/page.tsx:31` liste des packs faux (Starter 50 / Populaire 150 / Premium 500) ≠ grille réelle (refonte juin).
**Fix** : aligner sur les vrais packs ou renvoyer à `/shop`.

## P2 — Moyen
- `privacy/page.tsx` dit « pas de tracking » alors qu'Umami tourne → corriger après P0.1.
- `terms` affirme « PAS un jeu de hasard » alors qu'il y a des mini-jeux de hasard → **validation juridique** (contradiction + risque ANJ).
- Export RGPD incomplet (omet comments, adresse détaillée, auto-exclusion).
- Webhook redéfinit `new Stripe()` au lieu de `getServerStripe`.
- `database.types.ts` ne couvre pas `user_self_exclusion`/`set_self_exclusion` (3 `as any`) → re-régénérer.
- `ADMIN_ALERT_EMAIL` absent de `.env.example`.
- `PrivacyCard.handleExport` avale les erreurs silencieusement.
- `record_buy_it_now` : double-paiement même item (2 sessions) non remboursé (TOCTOU étroit).

## P3 — Mineur
- `getSelfExclusion` exporté jamais utilisé. `gift.ts` casts `as any` superflus (RPC typées). « CLIK/ZY » dans le header (legal)/layout. ResponsibleGamingCard boutons sans `aria-pressed`. Push copy « 10 clics » en dur. reset cron exclut `last_credits_reset` NULL.

## Validation JURIDIQUE (hors code, Mehdi/avocat)
Qualification ANJ (penny-auction + mini-jeux hasard = risque loterie/jeu d'argent), médiateur consommation (`legal.ts` null), adresse éditeur incomplète, formulation « pas un jeu de hasard ».

## Statut des corrections (2026-06-15, post-audit)

### Corrigé & shippé
- **P0.1** — `Analytics.tsx` lit `useCookieConsent()` et ne charge Umami **que** si `status === 'accepted'`. « Refuser » désactive réellement le tracking (conformité CNIL).
- **P1.2** — Auto-exclusion rendue non contournable : (a) `playMiniGame`/`playMiniGamePaid` vérifient `selfExcludedUntil` ; (b) **trigger DB** `trg_block_self_excluded` BEFORE INSERT sur `clicks` → `perform_click` (et tout INSERT direct) lève `self_excluded` pour un joueur en pause. Migration `20260615190001` appliquée + vérifiée en prod.
- **P1.3** — `register` : case 18+/CGU (`ageConfirmed`) déplacée AU-DESSUS du bouton Google ; `handleOAuth` et `handleSubmit` gardés ; bouton Google `disabled` tant que non cochée.
- **P1.4** — `jeu-responsable` & `comment-ca-marche` : `<main>` retiré (plus de double landmark), alignés sur `<article/div prose>` des pages sœurs.
- **P1.5** — `jeu-responsable` : section « Faire une pause » réécrite (self-service instantané au profil) ; retrait de la fausse promesse email 48h + de la « limite de dépense » non implémentée.
- **P1.6** — `cgv` : packs obsolètes remplacés par un renvoi à `/shop` (grille réelle).
- **P2** — `database.types.ts` régénéré (couvre `user_self_exclusion` + `set_self_exclusion`) ; `ADMIN_ALERT_EMAIL` ajouté à `.env.example` ; `PrivacyCard.handleExport` remonte les erreurs (plus d'avalement silencieux).
- **P3** — `getSelfExclusion` (mort) supprimé ; branding « CLIK »→« CLEEK » dans `(legal)/layout`.

> Note typage : le client serveur `@supabase/ssr@0.5.2` type mal `.rpc(name, args)` (args → `undefined`), au contraire du client `service_role`. Un cast étroit **documenté** reste sur le seul appel `set_self_exclusion` (la fonction + ses args sont validés côté DB). Ce n'est pas un type manquant.

### Reporté (assumé)
- **P1.1 — Fuite PII `profiles` → `authenticated`** : non corrigé. Le fix sûr = sortir `shipping_*`/`vip_subscription_id` vers une table dédiée (pattern `fair_server_seed`) OU grants-colonne + RPC profil complet. Lourd/risqué sur une DB de facturation fragile, et **pré-existant**. À planifier hors hotfix.
- **P2 juridique** (`terms` « pas un jeu de hasard », export RGPD incomplet, webhook `new Stripe()`) + **toute la validation JURIDIQUE de fond** : ressort de Mehdi/avocat (qualification ANJ, médiateur, adresse éditeur).
- **P3 cosmétiques** (aria-pressed, push copy en dur, reset cron `last_credits_reset` NULL) : sans impact conformité, à traiter en P2 refacto.

*2e passe. Le socle technique est sérieux ; les gaps conformité côté code sont corrigés (sauf P1.1 PII, reporté car structurel) ; reste la validation juridique de fond (Mehdi).*
