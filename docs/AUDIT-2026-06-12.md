# Audit complet Cleekzy — 12 juin 2026

Audit multi-angles (sécurité, frontend/UX, backend/data, qualité de code, complétude produit) + vérifications prod live (cleekzy.com).

**Verdict global : ~85 % production-ready.** Sécurité serveur excellente (aucune faille critique), économie de crédits étanche, ~90 % des features réellement implémentées de bout en bout. Les vrais problèmes sont produit (boucle de parrainage cassée, achats sans confirmation, zéro onboarding) et opérationnels (dépendance cron-job.org, crons manquants).

---

## 🔴 P0 — À fixer en priorité

### Bugs produit qui coûtent de l'argent
1. **Parrainage cassé à l'inscription** — le lien partagé est `/register?ref=CODE` mais la page register ne lit jamais `?ref` et `signUp` ne l'applique pas. Le filleul doit retaper le code à la main dans /profile. Toute la boucle virale est morte pour ~15 lignes de code. (`src/app/(auth)/register/page.tsx`, `src/actions/auth.ts`)
2. **Achat VIP/Passe d'Arène sans confirmation** — `LobbyClient.tsx` ne gère que `?payment=success&credits=` ; les retours Stripe `?pass=success` et `?vip=success` sont ignorés. L'acheteur ne voit RIEN après avoir payé → risque de double achat / chargeback.
3. **Cosmétiques premium inobtenables** — aucun `INSERT INTO user_cosmetics` nulle part (ni achat, ni récompense du Passe). Les SKU premium s'affichent verrouillés à vie dans `CustomizationSection.tsx`.
4. **Pas de handler Stripe `charge.failed` / `invoice.payment_failed`** — paiement échoué = silence total côté utilisateur.

### Fiabilité opérationnelle
5. **Dépendance critique à cron-job.org** — `vercel.json` n'a AUCUN cron. La clôture des parties (`bot-clicks` chaque minute) dépend d'un service externe : s'il tombe, plus aucune partie ne se termine. Ajouter un fallback (Vercel cron ou pg_cron).
6. **Race condition `endGame()`** — pas de `FOR UPDATE` : deux exécutions parallèles du cron peuvent créer deux `winners` pour le même jeu. (`api/cron/bot-clicks/route.ts:299-387`)
7. **Jackpot perdu si la distribution du 8 échoue** — `distribute_jackpot` skip si `day != 8`, aucun rattrapage le 9+. Élargir la fenêtre (8-10) ou vérifier `last_distributed_month`.
8. **Cron expiration des quêtes quotidiennes manquant** — les mêmes quêtes restent indéfiniment.
9. **Cron VIP expiry manquant** — `is_vip` reste true après `vip_expires_at`.
10. **`create-rotation` supprime TOUS les jeux `waiting`** — y compris les sains pas encore activés. Filtrer par `created_at < NOW() - 30min`. (`api/cron/create-rotation/route.ts:41-45`)
11. **Calcul minuit Paris en JS fragile (DST)** dans `reset-credits` — utiliser la RPC SQL `paris_midnight()` à la place. (`route.ts:36-52`)

### SEO / Acquisition
12. **robots.txt pointe vers l'ancien domaine clikzy.fr** (y compris la ligne Sitemap) — corrigé d'urgence, Google reçoit un mauvais pointeur. (`public/robots.txt`)
13. **`generateMetadata` sur 1 page sur 23** — lobby, collection, classement, gagnants, shop, vip, mini-games n'ont pas de meta dédiées. Canonical absent partout ; `og:url` = cleekzy.com sans www (incohérent avec l'host servi).
14. **Aucun onboarding nouveau joueur** — zéro tutoriel/première visite ; un nouveau arrive dans un lobby dense sans qu'on lui explique « dernier clic gagne ».
15. **Icônes PWA** — `manifest.json` référence `icon-192.png`/`icon-512.png` : vérifier qu'elles existent (sinon installation PWA cassée).

## 🟠 P1 — Important (rétention, monétisation, robustesse)

### Rétention (l'infra existe déjà, il manque le branchement)
- **Push « streak en danger » à 20h** — `sendPushToUser` + `streak_last_day` existent ; un cron suffit.
- **Relance inactifs par email** — seuls welcome + victoire existent. Manquent : streak qui expire, crédits non utilisés, coffres non ouverts.
- **Écran 0-crédit n'offre que payer** — rappeler les alternatives gratuites déjà codées (mini-jeux, quêtes, parrainage, coffres) dans `CreditPacksModal`.
- **Opt-in push enterré dans /profile** — le proposer après une victoire/near-miss.

### Monétisation
- **Passe d'Arène invisible** — rendu uniquement dans le modal calendrier. L'ajouter à /shop + upsell.
- **`/gagnants` orphelin** — pas de lien dans le header connecté ; la page de preuve sociale est invisible.
- **Boutique mono-produit** — /shop ne vend que les crédits ; pas de cross-sell VIP/Passe.
- **Abandoned cart** — `?payment=cancelled` ignoré, aucune relance.

### Sécurité / robustesse
- **Rate limiting absent** sur `clickGame()` / `playMiniGame()` / API publiques (Upstash documenté dans .env.example mais pas branché).
- **CSP affaiblie** — `unsafe-inline` + `unsafe-eval` dans script-src (passer aux nonces).
- **Tests manquants sur les modules critiques** : webhook Stripe (3 events), cron bot-clicks (élection gagnant, emails), collection (coffres/équipement).
- **Notifications sans retry** — push/email de victoire perdus si erreur ponctuelle (prévoir queue).
- **`getActiveGames()` sans limit** ; `daily_quests_status()` fait 6 sous-COUNT par appel.

### Frontend
- **129-143 console.log en prod** — gater par NODE_ENV ou Sentry.
- **Sitemap sans pages dynamiques** (`/joueur/[username]`).
- **Alt vides sur avatars** (LeaderboardClient), SVG sans aria-label, focus non trappé dans les modals, `text-white/40` sous le contraste AA.
- **Empty state lobby absent** (0 parties = page vide).
- **`<img>` natif en admin**, `unoptimized` sur l'image produit de game-client, `sizes` manquants.
- **Modals : feedback d'erreur** — CreditPacksModal se ferme sur erreur sans message.

## 🟡 P2 — Dette technique & améliorations

- **60+ `as any` sur les RPC Supabase** — créer des wrappers typés (`src/lib/rpc-types.ts`). Le plus rentable des refactos.
- **`LandingClient.tsx` 1510 lignes / `game-client.tsx` 1061 lignes** — découper en sections.
- **Duplications** : `RARITY_HEX` ×4, `RARITY_LABEL` ×2, `Slot`/`Equipment` ×3 → centraliser dans `src/lib/cosmetics.ts` / `src/types/equipment.ts`.
- **Tables orphelines** `xp_events`, `player_data_audit` (jamais lues) — DROP ou utiliser.
- **Endpoint mort** `api/cron/activate-games` (jamais planifié, redondant avec bot-clicks) — supprimer.
- **Purge `clicks`** — la table croît indéfiniment ; archiver > 90 jours.
- **ESLint trop permissif** — ajouter `no-explicit-any: error`, `no-console: warn`.
- **CI** : ajouter npm audit + bundle size analysis.
- **Clans V2** — recherche, page publique, gestion (kick/promote), avantages gameplay (actuellement seule feature sans récompense), quêtes de clan.
- **Em-dashes (—) dans le copy** (~25 occurrences : not-found, support, gagnants…).
- **Couleurs hors palette en dur** (#FFB800 etc.) — centraliser dans tailwind.config.
- **npm audit** : 2 vulnérabilités modérées PostCSS (en attente d'upstream Next).
- **page offline PWA** absente.

## ✅ Ce qui est déjà solide

- **Sécurité serveur de niveau avancé** : RPC SECURITY DEFINER partout, trigger de protection des colonnes sensibles (credits, is_admin, total_wins…), verrous `FOR UPDATE` sur `perform_click` (pas de TOCTOU), RLS strictes, webhook Stripe signé + idempotent (`stripe_events`), crons fail-closed sur CRON_SECRET, aucun secret en dur.
- **Économie étanche** : aucune fuite credits/earned_credits ; toutes les récompenses passent par earned_credits (permanent) ; seuls Stripe et le reset touchent credits.
- **Headers prod** : CSP, HSTS preload, X-Frame-Options, Permissions-Policy OK.
- **Couverture de tests correcte** : 14 fichiers unit + 7 e2e Playwright, CI lint/type/test/build + dependabot.
- **Features complètes** : jeu temps réel, crédits/VIP, XP/streak/quêtes/badges (dont cachés), coffres + perso équipable + bonus, calendrier + Passe, jackpot, mini-jeux provably-fair, push web, profil public.
